# Gmail Triage — Процедура AgentOS

## Когда вызывать

- По расписанию: каждые 2 часа (проверяй `../memory/check-log.md` — поле `gmail-scan`)
- Утром: часть `morning-brief` (ежедневно)
- Вручную: "проверь почту", "есть ли ответы на outreach?"

## Шаги

### 1. Получить непрочитанные письма

```
gmail_search_messages query "is:unread newer_than:2h"
```

**НЕ читать:** спам, промо-рассылки, автоматические уведомления от SaaS-инструментов.

### 1b. Получить исходящие письма (SENT)

```
gmail_search_messages query "in:sent newer_than:2h"
```

Цель: знать что Vasily отправил — чтобы contacts/*.md был актуален и система не "не знала" об уже отправленных инвойсах, договорах, follow-up.

**Фильтровать:** авто-уведомления (GitHub, ClickUp, Fireflies), нотификации от SaaS — не обрабатывать.

Для каждого исходящего письма:
1. Прочитать `gmail_read_message → message_id`
2. Извлечь: `To:`, `Subject:`, краткую суть
3. Сопоставить с контактом по алгоритму (см. раздел "Алгоритм SENT→Contact")
4. Записать в Timeline контакта: источник `[email-sent]`
5. Обновить `## Статус` контакта если письмо меняет pipeline (инвойс → ждем оплату, договор → DEAL и т.д.)

### 2. Прочитать каждое письмо

```
gmail_read_message → message_id
```

Или для получения треда с контекстом:
```
gmail_read_thread → thread_id
```

### 3. Классифицировать письма

Для каждого письма определить категорию:

| Категория | Признаки | Действие |
|-----------|---------|---------|
| **client** | от существующего клиента (Bailaspot, FemFast, Motobarn или другой активный) | Алерт в Telegram немедленно |
| **lead** | запрос на услуги, ответ на outreach, упоминание потребности | Сигнал `lead` в signals.md + алерт |
| **partner** | предложение о партнерстве, коллаборации | Сигнал `idea` в signals.md + алерт |
| **newsletter** | рассылки, дайджесты, промо | Прочитать заголовок, если нет инсайтов — игнорировать |
| **spam** | нерелевантные холодные письма, автоспам | Игнорировать |
| **internal** | от команды, автоматические (GitHub, ClickUp, Fireflies) | Игнорировать |

### 4. Извлечь сигналы

Для писем категорий `client`, `lead`, `partner` — записать в `../memory/signals.md`:

```
### [YYYY-MM-DD] {тип}: {краткое описание}
- **Источник:** gmail / {from email}
- **Потенциал:** high | med | low
- **Статус:** new
```

Типы:
- `lead` — если запрос на услуги или ответ на outreach
- `request` — если конкретный запрос/вопрос
- `problem` — если клиент сообщает о проблеме
- `idea` — партнерство, коллаборация

Потенциал:
- `high` — явный запрос/ответ на outreach/проблема клиента
- `med` — косвенный интерес, вопрос
- `low` — фоновый, информационный

## Алгоритм SENT→Contact

Для каждого исходящего письма сопоставить с контактом:

1. **Точное совпадение email:** проверить `To:` против `emails:` в секции `## Матчинг` каждого контакта
2. **Совпадение домена:** если точный email не найден — взять домен (например `@redtrack.io`) и найти контакт с `emails: *redtrack.io*`
3. **Совпадение по ключевым словам:** проверить `Subject:` против `keywords:` контакта
4. **Не найден:** если контакт не распознан — пропустить (не создавать файл для неизвестных получателей)

**Что записывать в Timeline:**

```markdown
### YYYY-MM-DD HH:MM [email-sent]
Vasily отправил: {Subject} — краткая суть (1 предложение).
```

**Обновлять `## Статус` при ключевых письмах:**

| Ключевые слова в Subject/body | Действие |
|-------------------------------|---------|
| invoice, инвойс, счет | Следующий шаг: "ждем оплату" |
| contract, договор, agreement | Pipeline: → DEAL (если ещё не DEAL) |
| follow-up, followup, напоминание | Следующий шаг: "ждем ответ" |
| proposal, КП, коммерческое | Pipeline: → PROPOSAL |
| DocuSign Remind | Следующий шаг: "договор на подписании" |

**НЕ обновлять статус** если письмо — автоматическое, нотификация, newsletter.

### 5. Event Correlation

Для каждого важного письма (client, lead) — вызвать скилл `event-correlation`:
- Определить контакт по email домена или адреса
- Записать в timeline контакта

### 5.5. Pre-alert cross-check

Перед алертом о клиентском письме или лиде — верифицируй:

1. **Читай timeline контакта:** `../memory/contacts/{slug}.md` — уже есть свежая запись об этом событии? Если да (дедупликация) — не алертить.
2. **Для reply на outreach** → проверь ClickUp статус контакта (если статус уже "PROPOSAL" или выше — алерт с контекстом, не с нуля).
3. **Для сигналов о сделках/договорах** (DocuSign, contract, подписание) → отдельно проверь signals.md — упоминалось ли это событие уже из другого источника?
4. **Если нашел противоречие** (Gmail говорит "подписал", а memory говорит "ждем") → алертить с пометкой "КОНФЛИКТ: Gmail и memory расходятся, проверь вручную".

Исключение: письмо от активного клиента (Bailaspot, FemFast, Motobarn) с конкретным запросом → алертить сразу.

### 6. Алерты в Telegram

**Немедленный алерт** для писем от клиентов и явных лидов:

Через agent-bus: send_message(from: "worker-{id}", to: "operator", topic: "task_complete", body: "результат")
Fallback: telegram MCP tool `telegram_send_message(chat_id: 123510069, text: "текст")`

Формат алерта:
- Кто написал (имя, компания если известна)
- Тема письма
- Одно предложение — суть
- Ссылка на письмо в Gmail (если есть публичная ссылка)

### 7. Обновить check-log

```
# В ../memory/check-log.md:
gmail-scan: YYYY-MM-DD HH:MM — N входящих, M исходящих, K важных
```

## Результат

- `../memory/signals.md` — новые сигналы из почты
- `../memory/contacts/*.md` — обновленные timeline: входящие через Event Correlation, исходящие через алгоритм SENT→Contact
- `../memory/check-log.md` — время последней проверки
- Telegram — алерты о важных письмах (только если есть что сообщить)
- **Нет "неизвестных" действий Vasily** — все исходящие письма отражены в contacts/*.md

## Правила

- НЕ читать спам и промо-рассылки — экономить контекст
- Клиентские письма → немедленный алерт (не ждать следующего цикла)
- Не дублировать сигналы — проверять что уже есть в signals.md
- Ничего нового → молчать, не отправлять в Telegram пустые отчеты
- Запускать как субагент с `run_in_background: true`
- Активные клиенты: Bailaspot, FemFast, Motobarn (могут появиться новые — смотри ClickUp pipeline)
