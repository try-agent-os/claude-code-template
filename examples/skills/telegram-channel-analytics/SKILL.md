# Telegram Channel Analytics — Процедура AgentOS

> Read-only research skill. Запускается в forked context — анализирует посты, возвращает структурированный отчёт.

## Когда вызывать

- После telegram-export: нужно понять что работает, какие темы, тренды
- Periodic review канала (еженедельно/ежемесячно)
- Перед созданием контент-стратегии на основе данных канала
- Пользователь спрашивает "что зашло в канале", "топ посты", "анализ канала"

## Входные данные

- **Slug канала** (обязательно) — папка в `resources/`
- **Категория** (опционально) — если не указана, ищи `resources/{slug}/` или `resources/outreacher/{slug}/` или `resources/telegram/{slug}/`
- **Период** (опционально) — по умолчанию все посты

## Шаги

### 1. Найти папку канала

```bash
# Проверь возможные пути:
ls "${CLAUDE_PROJECT_DIR}/resources/{slug}/posts/" 2>/dev/null
ls "${CLAUDE_PROJECT_DIR}/resources/outreacher/{slug}/posts/" 2>/dev/null
ls "${CLAUDE_PROJECT_DIR}/resources/telegram/{slug}/posts/" 2>/dev/null
ls "${CLAUDE_PROJECT_DIR}/resources/communities/{slug}/posts/" 2>/dev/null
```

Если папка не найдена — сообщи что нужно сначала запустить `telegram-export` для этого канала.

### 2. Прочитать все посты

Прочитай все `.md` файлы из `posts/`:

```bash
ls "${CLAUDE_PROJECT_DIR}/resources/{category}/{slug}/posts/"*.md | wc -l  # общее количество
```

Для каждого файла извлеки из frontmatter:
- `date` — дата поста
- `views` — просмотры (может быть `~` = нет данных)
- `reactions_total` — итого реакций
- `reactions` — строка с эмодзи и числами
- `forwards` — репосты
- `replies` — комментарии
- `has_media` — есть ли медиа

И из тела файла:
- Заголовок (первая строка `# ...`)
- Первые 200 символов текста (без `#` и frontmatter)

### 3. Рассчитать метрики

**Engagement score** (для ранжирования когда нет views):
```
engagement = reactions_total * 3 + forwards * 5 + replies * 2
```

**Топ-10 постов по реакциям** (или views если есть):
- Сортируй по `reactions_total DESC`, fallback на `views DESC`
- Если оба `~` — ставь в конец

**Топ-10 постов по просмотрам** (если views != `~`):
- Отдельный список если данные есть

**Частота постинга**:
```
# Сгруппируй по месяцам
# Посчитай среднее в неделю за последние 30 дней
```

### 4. Категоризировать темы

Прочитай текст каждого поста и определи тему по ключевым словам.

**Для outreach/B2B каналов:**
- `cold-email`, `offer`, `linkedin`, `follow-up`, `personalization`, `metrics`, `mindset`, `tools`, `case-study`, `other`

**Для контентных/экспертных каналов:**
- `tactics`, `strategy`, `case-study`, `tools`, `mindset`, `announcement`, `other`

Для каждой темы: количество постов, средние реакции, топ-1 пост.

### 5. Анализ трендов

**Динамика по месяцам** (если данных за 3+ месяца):
- Растет ли среднее engagement?
- Какой месяц был лучшим?

**Медиа vs текст**:
- Сравни среднее engagement для постов с медиа vs без

**Длина поста**:
- Короткие (<500 символов) vs длинные (>1000 символов) — что работает лучше?

### 6. Создать analytics.md

Файл `resources/{category}/{slug}/analytics.md`:

```markdown
---
channel: {slug}
analyzed_at: YYYY-MM-DD HH:MM
posts_analyzed: N
period: YYYY-MM-DD — YYYY-MM-DD
---

# Аналитика канала: {name}

> Анализ N постов за период YYYY-MM — YYYY-MM.

## Сводка

| Метрика | Значение |
|---------|---------|
| Постов проанализировано | N |
| Период | YYYY-MM — YYYY-MM |
| Ср. реакций на пост | X.X |
| Ср. просмотров на пост | X.X (или н/д) |
| Ср. постов в неделю | X.X |
| Постов с медиа | N (X%) |

## Топ-10 постов по реакциям

| # | Дата | Реакции | Просмотры | Краткое содержание |
|---|------|---------|-----------|-------------------|
| 1 | YYYY-MM-DD | N | N | [Ссылка](link) — краткое описание |
...

## Категории тем

| Тема | Постов | Ср. реакций | Лучший пост |
|------|--------|-------------|-------------|
| cold-email | N | X.X | [ссылка](link) |
...

## Тренды

### Динамика по месяцам

| Месяц | Постов | Ср. реакций |
|-------|--------|-------------|
| 2026-02 | N | X.X |
...

### Медиа vs текст
- Посты с медиа: ср. реакций X.X (N постов)
- Текстовые посты: ср. реакций X.X (N постов)
- **Вывод:** [медиа/текст] работает лучше на X%

### Длина постов
- Короткие (<500 символов): ср. реакций X.X
- Длинные (>1000 символов): ср. реакций X.X

## Ключевые инсайты

1. **[Главный вывод]** — [объяснение, данные]
2. **[Второй вывод]** — [объяснение, данные]
3. **[Третий вывод]** — [объяснение, данные]

## Рекомендации для контент-стратегии

- [Рекомендация 1 на основе данных]
- [Рекомендация 2]
- [Рекомендация 3]
```

### 7. Commit и push

```bash
cd "${CLAUDE_PROJECT_DIR}"
git add resources/{category}/{slug}/analytics.md
git commit -m "analytics: {slug} — N постов, топ темы: {top-3-topics}"
git push
```

## Правила

- Анализ read-only, не нужно подтверждение
- Если views = `~` для всех постов — использовать только реакции для ранжирования, явно указать в отчете
- Если постов < 10 — предупредить что данных мало, анализ ориентировочный
- Повторный запуск перезаписывает `analytics.md` (идемпотентный)
- Инсайты должны быть actionable — не просто "пост №5 был популярным", а "посты с числами в заголовке получают 2x реакций"

## Результат

- `resources/{category}/{slug}/analytics.md` — структурированный отчет
- Уведомить пользователя со ссылкой на отчет
