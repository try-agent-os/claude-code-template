# Outbound Tracker — Процедура AgentOS

## Проблема

Система видела только входящие: ответы контактов, reply на outreach.
Исходящие действия Vasily (отправил инвойс, написал follow-up, продублировал договор)
не фиксировались — из-за этого:
- contacts/*.md показывал "ждем" когда инвойс уже отправлен
- При проверке статуса сделки система видела "неполную картину"
- Workers алертили о "нужно отправить" когда действие уже было сделано

## Когда вызывать

- В составе `gmail-triage` (Шаг 1b) — автоматически каждые 2 часа
- В составе `telegram-scan` — после обработки входящих, проверять OUT сообщения
- Вручную: "что Vasily отправлял сегодня?", "обнови историю по {контакт}"

## Часть 1: Gmail SENT

### Получить исходящие

```
gmail_search_messages query "in:sent newer_than:2h"
```

Для более широкого окна (ручная синхронизация):
```
gmail_search_messages query "in:sent newer_than:24h"
```

### Фильтрация

**Пропускать (не обрабатывать):**
- Письма с noreply@, no-reply@, notifications@, support@ в From (автоответы)
- GitHub: github.com домен
- ClickUp, Fireflies, DocuSign (кроме Remind — это действие Vasily)
- Рассылки без To: конкретного человека (BCC-only)

**Обрабатывать:**
- Письма с конкретным человеком в To:
- DocuSign Remind (действие Vasily — нажал Remind)
- Ответы на входящие от клиентов/лидов
- Исходящий cold outreach

### Алгоритм сопоставления с контактом

```
для каждого письма в SENT:
  to_email = извлечь адрес из To:
  to_domain = домен из to_email (часть после @)
  
  1. Поиск точного email в contacts/*/ Матчинг:
     найти файл где emails: содержит to_email
     
  2. Если не найден — поиск по домену:
     найти файл где emails: содержит to_domain
     
  3. Если не найден — поиск по ключевым словам Subject:
     извлечь имя/компанию из Subject
     найти файл где keywords: содержит совпадение
     
  4. Если контакт не найден — пропустить
     (не создавать контакты для незнакомых адресатов)
```

### Запись в Timeline

```markdown
### YYYY-MM-DD HH:MM [email-sent]
Vasily → {To имя/email}: {Subject} — {суть 1 предложение}.
```

Примеры:
```markdown
### 2026-04-08 15:09 [email-sent]
Vasily → vladislav.derkach@redtrack.io: DocuSign Remind — отправил напоминание директору на подписание договора.

### 2026-04-08 13:48 [email-sent]
Vasily → vladislav.derkach@redtrack.io: Re: DocuSign — подтвердил email директора, нажал Remind в DocuSign.
```

### Обновление статуса контакта

| Признак письма | Обновление статуса |
|---------------|-------------------|
| Subject содержит "invoice" / "инвойс" / "счет" | Следующий шаг: "ждем оплату" |
| Subject содержит "contract" / "agreement" / "договор" | Pipeline: DEAL (если не DEAL) |
| Subject содержит "proposal" / "КП" / "offer" | Pipeline: PROPOSAL |
| Тело содержит DocuSign link | Следующий шаг: "ждем подписание" |
| DocuSign "Remind" | Следующий шаг: "договор на подписании, reminder отправлен" |
| Subject содержит "follow-up" / "following up" | Следующий шаг: "ждем ответ" |
| Subject содержит "Re: " (ответ на входящее) | Следующий шаг: "ответили {дата}, ждем реакцию" |

## Часть 2: Telegram OUT

Telegram исходящие уже частично покрыты в `telegram-scan`, но не всегда записываются в contacts/*.md.

### Источник данных

tdl JSON содержит поле `Out`:
- `"Out": true` — Vasily написал (исходящее)
- `"Out": false` — собеседник написал (входящее)

**Всегда маркировать направление при парсинге!**

### Алгоритм

```
для каждого сообщения в tdl-экспорте:
  если Out == true:
    это сообщение Vasily — обрабатываем как исходящее
    
    1. Определить контакт по chat_id или username чата
    2. Найти contacts/{slug}.md
    3. Проверить дедупликацию (есть ли запись за эту дату?)
    4. Записать в Timeline
    5. Обновить статус если сообщение ключевое
```

### Запись в Timeline

```markdown
### YYYY-MM-DD HH:MM [telegram-out]
Vasily → @username: краткая суть (1 предложение).
```

Примеры:
```markdown
### 2026-04-08 13:48 [telegram-out]
Vasily → @der_vlad: отправил скриншот DocuSign, подтвердил что нажал Remind на директора.

### 2026-04-08 09:55 [telegram-out]
Vasily → @der_vlad: спросил про апдейты по подписанию, Святослав не ответил.
```

### Ключевые паттерны Telegram OUT для обновления статуса

| Паттерн сообщения | Обновление |
|------------------|-----------|
| "отправил инвойс" / "выслал счет" | Следующий шаг: "ждем оплату" |
| "договор подписан" / "подписали" | Pipeline: DEAL |
| "КП отправил" | Pipeline: PROPOSAL |
| "стартуем" / "начинаем" | Следующий шаг: "активный клиент" |
| "встреча" / "созвон" / "звонок" в контексте расписания | Следующий шаг: "назначен созвон {дата}" |

## Результат процедуры

- `../memory/contacts/*.md` — Timeline обновлен: исходящие email и Telegram
- Статус контактов актуален: система знает что уже отправлено
- Нет расхождения между реальностью и memory

## Правила

- Никогда не приписывать исходящие сообщения контакту: `[email-sent]` / `[telegram-out]` явно указывают направление
- Дедупликация обязательна: проверять есть ли уже запись за эту дату+источник
- Не создавать контакты для неизвестных адресатов
- Исходящее ≠ событие для алерта в Telegram (не нужно нотифицировать о том что Vasily сам сделал)
- Исключение: если обнаружено что исходящее не отражено в memory уже 24ч+ — это можно упомянуть в morning-brief
