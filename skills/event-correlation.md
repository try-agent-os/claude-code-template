# Event Correlation — Процедура AgentOS

## Когда вызывать

- После каждого скана: gmail-triage, telegram-scan, calendar-проверка, fireflies-sync
- При создании нового события с упоминанием известного контакта
- Вручную: "запиши в timeline {имя} что {событие}"

## Шаги

### 1. Определить контакт

Для каждого события (письмо, встреча, задача, сообщение, транскрипт) определить к какому контакту оно относится.

Использовать секцию `## Матчинг` в файле контакта:

| Поле матчинга | Как проверять |
|--------------|--------------|
| `emails:` | домен или адрес отправителя/получателя |
| `telegram:` | @username автора сообщения |
| `keywords:` | имя, компания, продукт в subject/body |
| `linkedin:` | URL в сообщении |

Реестр контактов: `../../memory/contacts/` (все файлы).

### 2. Найти файл контакта

Путь: `../../memory/contacts/{slug}.md`

Slug = имя-фамилия, lowercase, дефис. Примеры:
- John Smith → `john-smith.md`
- Maria Lopez → `maria-lopez.md`

**Если файл не существует** и контакт важен (клиент, лид, партнер, нетворк) — создать новый файл по шаблону (см. ниже), затем вызвать скилл `contact-enrichment`.

**НЕ создавать** файлы для: спамеров, внутренних контактов команды, автоматических систем (notifications, bots).

### 3. Проверить дедупликацию

Перед записью — просмотреть секцию `## Timeline` контакта.

Не записывать если уже есть событие с той же датой и источником.

Проверка: есть ли запись `### {YYYY-MM-DD} ... [{источник}]`?

### 4. Записать в Timeline

Добавить запись в секцию `## Timeline` (новые записи — сверху, в хронологическом порядке):

```
### YYYY-MM-DD HH:MM [источник]
Краткое описание события — одно предложение.
```

Источники:
- `email` — письмо Gmail
- `telegram` — сообщение в Telegram
- `calendar` — событие в Google Calendar
- `docusign` — подписание документа
- `fireflies` — транскрипт встречи
- `linkedin` — активность в LinkedIn
- `scan` — обнаружен при сканировании (без прямого события)

Примеры записей:
```
### 2026-04-02 14:30 [email]
Написал о статусе проекта, просит обновление по срокам.

### 2026-04-01 10:00 [calendar]
Встреча — Discovery Call 45 мин. Обсудили требования к MVP.
```

### 5. Обновить статус (если нужно)

Если событие меняет статус контакта — обновить секцию `## Статус`:

```markdown
## Статус
- **Pipeline:** COLD | OUTREACH | DISCOVERY | PROPOSAL | DEAL | PARTNER | INACTIVE
- **Следующий шаг:** {что нужно сделать}
- **Последнее обновление:** YYYY-MM-DD
```

Триггеры для обновления статуса:
- Получен ответ на outreach → OUTREACH → DISCOVERY
- Проведен discovery call → DISCOVERY → PROPOSAL
- Подписан договор → DEAL
- Долго нет контакта → INACTIVE

### 6. Обновить people.md (опционально)

Если событие важное (новая сделка, изменение статуса, ключевая договоренность) — добавить краткую запись в `../../memory/people.md` к соответствующему контакту.

## Шаблон нового контакта

```markdown
# {Имя Фамилия} ({Компания})

## Контакт
- **Полное имя:**
- **Компания:**
- **Роль:**
- **Telegram:**
- **Email:**
- **LinkedIn:**
- **Источник:** откуда узнали

## Статус
- **Pipeline:** COLD
- **Следующий шаг:**
- **Последнее обновление:** YYYY-MM-DD

## Матчинг
- emails: domain.com, name@domain.com
- telegram: @username
- keywords: Company, Name, Product

## Связи
- **Общие чаты:**
- **Общие встречи:**
- **Через кого:**
- **Знает:**

## Timeline

### YYYY-MM-DD HH:MM [источник]
Первое обнаружение/упоминание.
```

## Результат

- `../../memory/contacts/{slug}.md` — обновленный Timeline и Статус
- `../../memory/people.md` — обновлен (если было важное событие)
- Если создан новый контакт — запущен скилл `contact-enrichment` (фоново)

## Правила

- Файлы контактов — source of truth для истории взаимодействий
- `memory/people.md` остается как индекс (ссылки и краткий статус), timeline живет в файле контакта
- При вопросе "что с {имя}?" — читать файл контакта, отдавать статус + последние записи timeline
- НЕ создавать файлы для: спамеров, команды, автоботов
- После обновления: git commit + push (вместе с другими изменениями цикла)
