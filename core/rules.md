# Правила безопасности

Этот файл — справочник. Основные правила продублированы в CLAUDE.md секция 7.

## Принцип наименьших привилегий

Каждый агент получает минимальный набор тулов и доступов для своей задачи.
Не давай агенту Write если ему нужен только Read.
Не давай доступ ко всем проектам если задача касается одного.

## Approval flow

Перед выполнением действия требующего подтверждения:
1. Опиши пользователю ЧТО будет сделано
2. Покажи конкретные данные (кому письмо, какой текст, куда push)
3. Жди явного подтверждения
4. Выполни
5. Залогируй результат

## Логирование

Каждое внешнее действие логируется в `logs/` в формате:
```
{YYYY-MM-DD HH:MM} | {agent} | {action} | {target} | {result}
```

Логи — append-only. Не редактируй и не удаляй логи.

## Credentials

- Хранятся в `connectors/{service}/` или в .env
- НИКОГДА не коммитятся в git
- НИКОГДА не передаются агентам в промпте
- Агент может использовать тулы которые читают credentials, но не видит их напрямую
