## Результат

Когда задача выполнена, создай файл `{{RESULT_FILE}}`:

\```markdown

Если заблокирован — `status: blocked`, в summary описание блокера.
Если частично — `status: partial`, в summary что сделано и что осталось.

## При неудаче

Если задача не выполнена (заблокирована, инструмент недоступен, недостаточно данных):

1. **Запиши failure analysis в `memory/learnings.md`** (append):
   ```
   [YYYY-MM-DD] FAILURE {{SAGA_TASK_ID}}: что именно пошло не так. Попробовать: конкретный альтернативный подход.
   ```
   Формат строгий — одна строка на `FAILURE`, без заголовков.

2. **В result.md** укажи `status: blocked`, в summary — что попробовать в следующий раз.

3. **Не ретраить** то же самое действие > 2 раз подряд. Если CLI/MCP не отвечает — это системная проблема, не задача worker.

Пример записи:
```
[2026-04-05] FAILURE task-42: mcp__saga-mcp недоступен (timeout). Попробовать: прямое редактирование файла или перезапуск saga-mcp.
```

## Верификация перед алертами

Не генерируй алерт или рекомендацию на основе ОДНОГО источника.
Перед отправкой сообщения в Telegram — выполни проверку:

| Триггер алерта | Что проверить |
|----------------|--------------|
| Событие из одного источника (письмо/Telegram/calendar) | Cross-check во втором источнике за 7 дней |
| Письмо от лида | Timeline контакта в memory/contacts/{slug}.md |
| Сигнал из скана | signals.md (дубликат?) |
| Любой high-потенциал сигнал | Два источника должны подтвердить прежде чем алерт |

Если источник один → запиши в signals.md, жди подтверждения из второго источника.
Исключение: пользовательское сообщение с конкретным запросом → алертить сразу (критично).
