# Calendar Management — Правила (шаблон)

> **Это шаблон.** Замени названия клиентов/проектов и времена recurring-событий под себя при первом использовании. Цветовая система (5 колонок) — рекомендованный baseline для AgentOS, но менять можно.

## Когда вызывать

При любом действии с календарем пользователя:
- `mcp__claude_ai_Google_Calendar__create_event`
- `mcp__claude_ai_Google_Calendar__update_event`
- `mcp__claude_ai_Google_Calendar__delete_event`
- Когда планируем работу/неделю/день (пользователь просит "запланируй", "поставь", "добавь в календарь")

## КРИТИЧНО: pre-flight check

**ВСЕГДА перед созданием новых events на день — вызывать `list_events` на этот день.**

Цель:
- Не создавать дубликаты с recurring-событиями (lunch, dinner, walks, wind-down, sleep и т.д.)
- Не создавать дубликаты с meetings, которые уже стоят
- Не создавать дубликаты с другими блоками которые я сам же создал ранее
- Видеть свободные окна реально, не из памяти

**Никогда не создавать events "на ощущение свободного слота" — всегда сначала `list_events`.**

## Цветовая система (рекомендованный baseline)

**Только 5 цветов / категорий. Других не использовать.**
Если событие не вписывается в одну из 5 — выбрать ближайшую, не изобретать новую категорию.

| Категория | colorId | Цвет в Google | Что относится |
|-----------|---------|---------------|---------------|
| **Meetings** | `6` | 🟠 Tangerine | Внешние встречи, calls, инвестор-коллы, интервью с клиентами |
| **Focus Work** | `5` | 🟡 Banana | Deep work на клиентских проектах, продуктовая разработка |
| **Personal** | `2` | 🟢 Sage | Тренировки, lunch, dinner, walks, sleep, wind-down, break |
| **Operations** | `7` | 🔵 Peacock | Planning, finance, admin, chats EOD, taxes, backoffice, content |
| **Growth** | `3` | 🟣 Grape | Learning, новые идеи, networking, market research, рост каналов |

### Проверка перед созданием

Если категория неоднозначна — спросить пользователя ОДНИМ вопросом, не выдумывать.

## Маркеры проектов в title (emoji prefixes)

Все Focus Work события одного цвета (Banana, 5). Проекты различаются emoji-кружком в начале title:

| Проект | Emoji prefix |
|--------|--------------|
| Project A | 🟣 |
| Project B | 🟢 |
| Project C | 🔴 |

(Замени на свои проекты при настройке.)

Категория событий ОСТАЕТСЯ Focus Work (5). Цветной кружок — это маркер ПРОЕКТА в названии, не цвет события.

**Названия — короткие.** Просто проект, без уточнений (`deep`, `kickoff`, `other tasks`, `block`). Это просто блок-маркер. Уточнения — в description.

Примеры (правильно):
- `🟣 Project A`
- `🟢 Project B`

Неправильно:
- ❌ `🟣 Project A block`
- ❌ `🟢 Project B kickoff`

## Язык событий

Рекомендация: все события — на одном языке (английский — простой выбор для интернационального контекста). Это правило стилевое; меняется при настройке.

Хорошо:
- 💪 Strength training
- 🟢 Project B block
- 📞 Discovery call: review product + questions
- ☕ Break
- 🍽️ Dinner

Emoji в начале title — норма (визуальный маркер). Description можно по-русски.

## Recurring events (заполняется пользователем)

Перед созданием rhythm-events ВСЕГДА вызвать `list_events` на день. Типичные recurring (адаптируй под себя):

| Событие | Время | Цвет | Не дублировать |
|---------|-------|------|----------------|
| 🐕 Morning walk + coffee | 08:00-09:30 | Personal (2) | Никогда не создавать |
| 📱 Check messengers / inbox | 09:30-09:45 | Operations (7) | Никогда не создавать |
| 🥗 Lunch | 13:00-13:45 | Personal (2) | Никогда не создавать |
| 💬 Check chats (EOD) | 18:00-18:15 | Operations (7) | Никогда не создавать |
| 🍲 Dinner | 18:30-19:00 | Personal (2) | Никогда не создавать |
| Wind-down | 22:30-23:00 | Personal (2) | Никогда не создавать |
| Sleep | 23:00-07:30 | Personal (2) | Никогда не создавать |

ПЛЮС встречи (recurring meetings, sync planning) — проверять перед созданием новых.

## Стандартные блоки работы

| Блок | Длительность | Цвет |
|------|--------------|------|
| Deep work block (клиентские проекты) | 1.5ч (90 мин) | Focus Work (5) |
| Operations / chats | 1ч | Operations (7) |
| Content batch | 1ч | Operations (7) |
| External call | 30-60 мин | Meetings (6) |
| Break | 15-30 мин | Personal (2) |
| Planning continuation | 15-45 мин | Operations (7) |
| Финансовый ритуал (раз в неделю) | 1.5ч | Operations (7) |

## Принципы планирования (адаптируй под себя)

- **Не более 3 главных дел в день** — защита от перегрузки.
- **Free time buffer** — минимум 30% свободного времени на неделю.
- **Тренировки фиксированные первыми** — ядро недели, остальное вокруг.
- **Один день в неделю — FOCUS DAY** — никаких meetings.
- **Конец недели** — weekly review + план на следующую неделю.
- **Wind-down/sleep** — защита, не двигать.

## Workflow создания недельного плана

1. Пользователь просит запланировать неделю (или конкретный день)
2. Спросить какие фиксированные events на неделе (тренировки, клиентские встречи)
3. Вызвать `list_events` на каждый день — увидеть существующие recurring + meetings
4. Поставить тренировки первыми (Personal 2)
5. Вокруг них раскидать work blocks (Focus Work 5)
6. Operations / Finance / Planning слоты (Operations 7)
7. Content batch (Operations 7)
8. Не создавать дубликаты с recurring
9. Показать сводку дня в Telegram → пользователь ОК → следующий день

## Workflow исправления конфликтов

Если событие пересекается с уже существующим:
- Если recurring (lunch/dinner/walk/wind-down) — НЕ двигать recurring, двигать свое
- Если meeting — НЕ двигать, двигать свое
- Если оба мои — пересмотреть приоритет, спросить пользователя если не очевидно
